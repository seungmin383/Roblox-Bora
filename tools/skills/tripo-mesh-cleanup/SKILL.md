# Tripo 생성 → Blender 메시 정리

Tripo가 만든 전체 실루엣과 디자인을 기준으로, 필요한 부위만 측정하고 재구성한다. 목표는 **원형의 인상을 유지하면서 솔리드에서도 깔끔하고 용도에 맞게 가벼운 모델**이다. AI가 만든 찌그러짐과 불규칙한 삼각형까지 보존하지 않는다.

## 작업 모드와 범위

- **새 자산:** Tripo로 전체 형태를 먼저 만든 후 Blender에서 수정한다. 초기부터 단순 도형으로 최종 외형을 대체하지 않는다. 기본 도형은 생성 결과의 평면 부품·받침·볼트 등을 재구성할 때 활용한다.
- **기존 자산:** 현재 생성본과 사용자가 승인한 수정본에서 이어간다. 일부 문제가 있다고 전체를 다시 생성하지 않는다.
- 사용자가 ‘대답만’, ‘구상만’이라고 하면 설명에서 멈춘다. 그 외 실행 요청은 모델링과 검증까지 진행한다.
- 부품 분리는 실제 사용 목적에 맞춘다. 자동차 문·바퀴·핸들처럼 움직이는 부품은 별도 오브젝트와 피벗이 필요하지만, 모든 자산에 같은 분리 규칙을 적용하지 않는다.
- 생성·크레딧 사용·배포는 현재 요청에서 허용된 범위로 진행한다. 스킬 호출만으로 계정 설정이나 공개 범위를 바꾸지 않는다.

## 원본과 작업 상태 확인

프로젝트 지침, 기존 생성본·수정본·내보내기 도구와 열려 있는 편집 상태를 확인한다. 원본과 승인된 결과를 구분하고, 수정하지 않을 자산은 해시 또는 해당 면의 좌표 서명으로 보존 여부를 기록한다. 모델 파일을 저장할 때 기존 작업을 덮어쓰지 않도록 현재 파일 소유·저장 상태를 확인한다.

사용 가능한 Tripo 도구나 연결된 브라우저로 생성 작업을 수행한다. 계정·API·다운로드 경로를 추측하지 않는다. 새 생성이 필요하면 대상 플랫폼, 주요 실루엣, 재질, 내부가 필요한지, 움직일 부품을 프롬프트에 반영한다. 외관 선택에는 표면이 보이는 여러 각도의 미리보기를 이용한다. 생성 결과의 파일, 작업 ID, 원본 폴리곤 수를 확보할 수 있는 범위에서 기록한다.

Blender와 프로젝트 도구는 가능한 경우 백그라운드로 실행한다. 앱 실행·데스크톱 전환에 관한 사용자 선호와 프로젝트 지침을 따른다. 실행 파일 경로를 하드코딩하지 말고 환경에서 찾는다.

## 부위별 정리

먼저 원본을 **솔리드와 와이어프레임 양쪽**에서 살핀다. 치수·실루엣·두께·단차·부품 위치를 측정하고, 원본 형상과 생성 결함을 구별한다. 한 번에 선택한 부위를 정리하고 이전에 승인된 부위는 보존한다.

| 형상 | 선호하는 정리 |
| --- | --- |
| 넓은 평면 | 실제 평면으로 맞추고 불필요한 내부 선을 합친다. 평평한 큰 면은 적절한 n-gon도 가능하다. |
| 긴 모서리·직각 | 경계선을 곧게 정렬하고 연속된 모서리 구조와 필요한 작은 베벨을 만든다. |
| 원형 테두리·곡면 | 측정한 중심·반지름·단면을 따라 규칙적인 루프를 배치한다. |
| 차양·케이스 벽 | 외벽·내벽·앞 립·연결 면을 구성해 실물 두께를 가진 닫힌 셸로 만든다. |
| 작은 받침·클립·리브 | 위치와 인상은 유지하되 단순한 닫힌 메시로 재구성한다. 작은 생성 요철을 재현하는 데 비용을 쓰지 않는다. |
| 창·내부·관절 | 실제 유리와 내부 공간, 분리 부품과 피벗 등 사용 목적에 맞는 구조로 만든다. 그림으로만 기능을 흉내 내지 않는다. |

세부 구현 전에 [modeling.md](references/modeling.md)의 해당 부분을 읽는다. 특히 면 재구성·두께·노멀·베이크의 상호작용을 확인한다. 모델별 치수와 허용 오차를 정하며, 다른 자산에서 사용한 수치를 그대로 적용하지 않는다. 유기적 형상은 필요한 실루엣과 변형 흐름을 보존하고, 하드서피스처럼 각지게 강제하지 않는다.

Decimate, Limited Dissolve, 자동 리메시, Shade Smooth는 보조 수단이다. 그것만 적용하고 리토폴로지나 평면 정리가 끝났다고 말하지 않는다. 모든 면을 사각형으로 바꾸는 것도 목표가 아니다. 편집 메시와 최종 내보내기의 삼각형 수를 구분한다.

## 재질·검증·납품

새 형상에 UV와 색상을 맞추되, 원본에 구워진 찌그러짐·조명 얼룩을 새 평면과 곡면에 다시 입히지 않는다. 새 부품의 노멀을 보호하고 UV 편집 이후 최종 저장·내보내기 단계에서도 확인한다.

완료 판정에는 다음 증거가 필요하다.

- 문제가 있던 각도에서 솔리드와 실제 편집 와이어프레임을 확인했다.
- 새로 만든 두께 셸과 작은 고형 부품에 열린 경계·비다양체 모서리·뒤집힌 면·퇴화 면이 없는지 검사했다. 원본의 기존 열린 부분은 새로 만든 부분과 구분한다.
- 저장한 파일을 다시 읽어 면 구조, 노멀, UV와 부품 크기·위치를 확인했다. 승인된 부위와 원본·프로젝트 보존 여부를 비교했다.
- 필요한 경우 원본과의 양방향 거리·실루엣을 비교했다. 의도적으로 단순화한 부품의 오차는 별도로 기록하고, 검사를 통과시키려고 전체 허용 오차를 넓히지 않는다.
- 최종 대상 형식의 삼각형 수·노멀·UV·스케일·피벗을 확인했다. 수정 파일 제작과 실제 게임/배포 반영을 구분해 보고했다.

반복 가능한 기초 검사는 [inspect_blend.py](scripts/inspect_blend.py)를 쓴다. 이 도구는 파일을 수정하지 않고 선택한 오브젝트/태그 면의 구성 요소, 열린 경계, 비다양체 모서리, 퇴화 면, 유한 좌표·UV·노멀을 JSON으로 기록한다. 시각적 품질이나 실루엣을 자동으로 보증하지 않는다.

```powershell
& $blenderExe --background --python-exit-code 1 --python '<skill>/scripts/inspect_blend.py' -- '<asset>.blend' --output '<audit>.json' --object '<mesh-name>' --require-closed
```

일부 새 부품만 검사하려면 `--face-tag DisplayFace --face-tag DetailFace`처럼 실제 파일의 FACE/INT 속성을 지정한다. 전체 원본이 열려 있어도 선택한 새 부품의 닫힘은 별도로 검증할 수 있다. 태그와 오브젝트 이름은 예시이며 파일에서 확인한다.

최종 답변에는 바꾼 부위, 검사 결과, 수정 파일 링크와 유용한 솔리드 미리보기를 간결하게 제시한다. 사용자가 다시 열어야 하는 파일과 실제 적용 여부를 명확히 한다.

Ro 신호등을 이어서 작업할 때만 [ro-workflow.md](references/ro-workflow.md)를 읽어 기존 도구와 보존 규칙을 재사용한다. 이 프로젝트의 규칙을 다른 프로젝트의 기본값으로 취급하지 않는다.
