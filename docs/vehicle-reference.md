# 자동차 제작 참고 기준

2026-10-18 사용자 제공 예시를 Blender 백그라운드에서 직접 열어 분석했다.

## 사용자 판단과 작업 범위

- 사용자는 `assets/example/Car/temp.blend`의 외장과 실내 품질을 좋은 참고로 선정했다. 특정 디자인을 모든 차량에 강제하는 절대 규격은 아니다.
- 사용자는 마지막 `BoraS2_FitFix`를 매우 나쁜 결과로 평가했다. 해당 결과는 승인된 기반도, 품질 기준도 아니다. 이후 제작에서 그대로 이어 쓰거나 성공 사례로 제시하지 않는다.
- 기존 Bora의 자동 메시 검사 통과는 시각적 품질에 대한 사용자 승인이 아니다. `BoraS2_Clean` 역시 사용자 승인을 추정하지 않는다.
- 최초 참고 분석 단계에서는 예시 원본, 기존 Bora 파일, `Ro.rbxlx`를 수정하지 않았다. 이후 제작·승인·게임 적용 상태는 아래에 별도로 기록한다.

## 직접 확인한 자료

- 원본: `../assets/example/Car/temp.blend`
- 원본 SHA-256과 전체 구성: `../assets/vehicles/reference-study/car-reference-inventory.json`
- 외장 전면/후면: `reference-front-solid.png`, `reference-rear-solid.png`
- 실내 분리/운전석 근접: `reference-interior-solid.png`, `reference-cockpit-solid.png`
- 실제 편집 모서리: `reference-front-wire.png`
- 위 이미지들은 모두 `../assets/vehicles/reference-study/`에 있다. 재질·텍스처 품질 평가용이 아닌 중성 Workbench 구조 확인 이미지다. 실내 분리 이미지에서는 외장·유리·내장 패널 일부를 숨겼다.
- 재현: `tools/analyze_car_reference.py`, `tools/render_car_reference.py`. 원본을 열어 메모리에서만 분석/렌더하며 `.blend` 저장을 호출하지 않는다. `--disable-autoexec`로 실행했다.

## 측정 결과와 해석

| 항목 | 확인 내용 |
| --- | --- |
| 메시 오브젝트 | 59개, 이름 `st-001`부터 `st-059` |
| 편집 메시 | 375,868정점, 342,986면. 모든 면이 사각형 |
| 삼각분할 시 | 685,972삼각형. Roblox용 예산의 확정값이 아니라 참고 원본의 밀도 |
| 모디파이어 | 없음. 낮은 밀도의 제어 케이지가 남아 있다고 가정하지 않는다 |
| 타이어 | `st-004/010/012/014`, 각각 60,000삼각형. 네 타이어만 전체의 약 35% |
| 실내 | `st-003`에 좌석·핸들·대시보드·룸미러 등이 함께 들어 있다. 25,964삼각형 |
| 외장 구성 예 | `st-033` 보닛, `st-007/038` 전면 주변, `st-006/023` 문 영역. 기능 명칭은 분리 렌더와 위치로 해석한 것 |
| 앞유리 | `st-040`, 568사각면. 유리 면도 휘어진 차체 경계를 따른다 |

| 기초 구조 검사 | 경계 모서리 62,316개, 면 3개 이상 연결된 모서리 0개, 면적 1e-12 미만 면 0개 |

열린 경계 수만으로 이 모델이 나쁘다고 판단하지 않는다. 개별 패널과 분리된 표면의 열린 가장자리, 의도하지 않은 관통 구멍을 구분해야 한다. 반대로 닫힌 메시만으로 잘 맞는 외장과 실내가 보장되지도 않는다. 이번 검사에서 자기 교차·유리 간격·문 개폐 충돌을 전수 검증한 것은 아니다.

일부 텍스처는 packed 상태이며, 기존 제작자 경로를 가리키는 누락 이미지 항목도 있다. 중성 구조 렌더에는 영향을 주지 않는다. 현재 폴더에는 라이선스 문서가 없어 실제 게임 반입·변형·재배포 권한은 확인하지 않았다. 이번에는 참고 관찰만 수행했다.

## 앞으로 적용할 제작 기준

1. **실루엣과 큰 면부터 맞춘다.** 길이·폭·높이·축거·캐빈 위치를 새 차종에 맞춰 잡는다. 이 예시의 외형이나 수치를 다른 차에 그대로 강제하지 않는다.
2. **면 흐름은 디자인 선을 따른다.** 보닛의 솟은 부분, 휠 아치, 범퍼 코너를 따라 루프를 놓고 굴곡과 단차에 필요한 밀도를 준다. 사각형 개수 자체를 목표로 삼지 않는다.
3. **인접 패널은 함께 설계한다.** 보닛·펜더·범퍼·램프의 경계 위치와 곡면 흐름을 맞춘다. 각 부품을 따로 닫거나 덮개를 붙여 외부 틈을 감추는 것으로 완료하지 않는다.
4. **패널 틈과 관통 구멍을 구별한다.** 일정한 틈, 안쪽 리턴 면과 받침 구조를 설계한다. 모든 패널을 용접해서 경계를 없애는 것도 목표가 아니다.
5. **실내 공간을 먼저 확보한다.** 유리·필러·지붕·문 안쪽을 기준으로 대시보드·좌석·핸들을 배치한다. 대시보드는 유리 하단 곡선과 폭을 따라야 한다. 사각 블록을 넣고 바깥으로 튀어나온 부분만 잘라내는 접근을 반복하지 않는다.
6. **사용 목적에 맞게 분리한다.** 참고 파일에 함께 묶인 부품이 있어도 주행용 차량에는 좌우 문·바퀴·핸들의 분리와 올바른 피벗이 필요하다. 예시의 오브젝트 분할을 그대로 런타임 구조로 간주하지 않는다.
7. **작은 구역부터 확인한다.** 다음 제작에서는 차체 전체를 한 번에 완성했다고 전달하기 전에 앞코 접합부나 캐빈처럼 좁은 부위의 솔리드·와이어·근접 결과를 확인한다. 사용자가 거부한 결과를 자동 검사 통과를 근거로 다음 기반으로 승격하지 않는다.
8. **품질 판정과 최적화를 구분한다.** 전후좌우 실루엣, 접합부 근접, 실내/실제 운전 시야를 먼저 확인하고, 적절한 삼각형 예산과 LOD를 정한다. 원본의 68만 삼각형을 그대로 복제하거나 전체 Decimate만으로 게임용 완성이라 하지 않는다.

이 기록은 AI 자체를 재학습한 결과가 아니다. 다음 작업에서 다시 읽을 수 있는 구조 관찰과 제작 판단 기준이다. 예시 수준의 모든 차종을 자동으로 제작할 수 있다는 보장으로 사용하지 않는다.

## 이후 새 제작 작업본

사용자의 "다시 자동차 만들기 시작해" 요청으로 `assets/vehicles/BoraS3/BoraS3.blend`와 `BoraS3.glb`를 새로 제작했다. 제작 진입점은 `tools/build_bora_s3.py`이며, `tools/car_surface_tools.py`가 표면 도구다. `tools/review_bora_s3.py`와 `tools/validate_s3_glb.py`로 저장본을 확인한다. 예시 메시를 복사하거나 거부된 FitFix를 기반으로 사용하지 않았다.

2026-10-18 핸들 하단 연결과 운전자를 향하는 방향을 교정한 뒤 사용자가 “이정도면 오케이 모델 전부 프로젝트에”라고 승인·적용을 요청했다. 이 S3를 현재 프로젝트 모델로 사용한다. 파일과 실제 검증 범위는 `assets/vehicles/BoraS3/README.md`, `audit.json`, `glb-validation.json` 및 `dist/model-application-validation.json`에 기록한다. 승인 원본을 유지하고 native 렌더 메시 84개로 합쳐 유일한 `Ro.rbxlx`의 기존 차량에 반영한다. 이전 S2/FitFix에 대한 거부 판단은 유지한다.
