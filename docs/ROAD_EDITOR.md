# 지도 기반 도로 편집 v0.6

유일한 프로젝트는 최상위 `Ro.rbxlx`입니다. 기존 나무와 맵 배치를 보존하고 `BoraMapReference`와 도로 도구만 추가합니다. 새 Place는 만들지 않습니다.

## 사용

1. Studio의 플러그인 탭에서 **지도 · 도로**를 엽니다.
2. **지도 위에서 보기**를 누릅니다. 첨부된 `naver_map (2).png`를 로컬 참고 이미지로 설치했습니다. 실제 거리로 확정된 지도는 아닙니다.
3. 실제 거리를 아는 두 지점 사이의 거리를 m로 입력하고 **축척 맞추기**를 누른 뒤 지도 위에서 두 점을 찍습니다. 분홍 측정선의 총거리 3.2km를 두 점 사이 직선거리로 사용하지 않습니다.
4. **도로 그리기 → 새 도로 그리기**에서 지면에 점을 차례로 찍습니다. 반투명 도로가 미리 보입니다. Enter 또는 확정 버튼으로 저장합니다. Backspace는 마지막 초안 점 취소, Esc는 작업 취소입니다.
5. 도로를 선택하고 **선택 도로 · 점 편집**을 누르면 빛나는 점을 드래그할 수 있습니다. 점 추가·삭제와 개별 점 높이 변경도 가능합니다.
6. 도로 폭, 전체 차선 수, 양쪽 인도 폭, 곡선의 완만함, 노면 높이 보정을 슬라이더나 숫자로 조절합니다. 슬라이더를 놓으면 적용됩니다. 골목/왕복 2차선/왕복 4차선 프리셋이 있습니다.
7. Ctrl+Z/Ctrl+Y로 변경을 되돌리거나 다시 실행합니다. 저장은 항상 `Ro.rbxlx`에 합니다.

## T자 · 십자 교차로

새 도로의 **시작점 또는 끝점**을 기존 도로의 중심선 중간에 가깝게 찍고 Enter로 확정하면 자동으로 연결합니다. 스냅 거리는 8 studs이며, 기존 도로 끝 근처는 이전처럼 끝점에 붙습니다. T자 진입 각도는 약 45~135도로 그립니다. 너무 짧은 도로나 다른 교차로에 너무 가까운 연결은 안내 후 적용하지 않습니다.

십자 교차로는 두 가지 방식으로 만듭니다. 기존 도로를 **가로질러 반대편까지** 새 도로를 그리고 Enter로 확정하거나, 기존 **T자 연결점의 반대편**에서 새 도로의 시작·끝점을 붙입니다. T자 연결점 근처에서는 같은 중심점으로 스냅해 하나의 십자 교차로로 합칩니다. 교차로 모양은 확정하거나 점을 놓은 뒤 생성됩니다.

두 도로가 중간에서 교차하면 샘플 중심선의 교점을 자동 계산합니다. 네 방향의 인도 모서리를 둥글게 잇고 교차로 안의 차선을 비웁니다. 폭·위치를 바꾸면 함께 다시 계산하며, 도로를 떼면 기존 노면·인도·차선을 복구합니다. 십자에서 가지 하나를 삭제하면 T자로 돌아갑니다. 외부 삭제 후에는 **교차로 다시 계산**을 누릅니다. 노면 높이가 0.35 studs보다 많이 다른 입체 교차는 자동 연결하지 않습니다.

- 연결부의 기존 노면·인도·차선을 정확한 절개 위치에서 끊고, 빈 노면과 둥근 인도 모서리를 채웁니다. 진입부를 가로막는 인도와 교차로 안의 차선은 남기지 않습니다.
- 가지 도로의 연결점을 기존 도로를 따라 드래그하면 연결 위치를 바꿀 수 있습니다. 멀리 떼어 놓으면 연결을 해제하고 기존 도로의 인도와 차선을 복구합니다.
- 기존 도로의 점을 움직이면 연결된 가지 도로 끝도 따라갑니다. 도로 폭·인도 폭·높이를 바꿔도 연결부를 다시 계산합니다. 갱신 시점은 점/슬라이더를 놓을 때입니다.
- 연결부를 클릭해도 가지 도로를 선택할 수 있습니다. 외부 도구로 도로를 삭제·변경한 뒤에는 패널 아래의 **교차로 다시 계산**을 누릅니다.
- 가지 도로의 `JunctionLinks`에 대상 도로의 ObjectValue와 중심선 길이 비율 `At`, `Start`/`End`를 저장합니다. 기존 도로 점 개수와 ObjectId를 바꾸지 않습니다. `BoraRoads.Junctions`에 생성 형상을 저장하므로 Play에서도 일반 충돌 부품으로 유지됩니다.
- `BoraRoads.Junctions`의 교차로에는 ArmCount(3/4), Center, Members의 도로 참조를 저장합니다. 중간에서 교차하는 두 도로의 교점은 각 도로의 Nodes에서 다시 계산하며, 별도 끝점 연결은 만들지 않습니다.
- 다섯 방향 이상, 아주 좁은 간격의 연속 교차로, 순환하는 연결 의존성은 이번 버전 범위에 포함하지 않습니다. 모든 형상을 준비한 뒤 한 번에 적용하므로 잘못된 연결은 기존 맵을 일부만 바꾸지 않습니다.

## 저장과 형상

### 차로별 진행 방향

1. 도로를 선택하고 상단의 **차로 방향** 탭을 엽니다.
2. **진입로 표시 · 번호 클릭**을 누릅니다. 최초 사용 시 필요한 교차로 정보를 재계산합니다.
3. 월드의 빛나는 번호 또는 **이전/다음 진입로**로 편집할 방향을 고릅니다. **선택 진입로 위에서 보기**로 해당 위치를 볼 수 있습니다. 양쪽에서 교차로로 들어오는 방향은 각각 따로 편집합니다.
4. 차로별 **좌회전·직진·우회전** 버튼을 켜거나 끕니다. 초록이 허용 방향이며 복수 선택할 수 있습니다. 연결 도로가 없는 방향은 회색입니다. 최소 한 방향은 남겨야 합니다. 예를 들어 직진에서 좌회전 전용으로 바꾸려면 좌회전을 켠 뒤 직진을 끕니다.
5. 버튼을 누르면 즉시 저장·반영됩니다. Ctrl+Z/Ctrl+Y가 가능하며 Esc 또는 다른 탭으로 나가면 진입로 표시를 종료합니다.

차로 번호는 교차로로 진입하는 운전자 기준 중앙선 쪽부터 1차로입니다. 현재 도로의 전체 차선 수를 양방향으로 나눕니다. 전체 4개는 방향별 2개, 전체 6개는 방향별 3개입니다. 홀수 3개/5개는 도로 제어점 순서의 끝점 방향에 한 차로를 더 배정합니다. 노란 중앙선과 정지선도 이 분할에 맞춥니다. 전체 1개는 공유 단일 차로입니다. 구간별 차선 증감·일방통행 지정은 아직 포함하지 않습니다.

화살표는 각 진입 차로의 정지선 뒤에 생성하며 도로 폭·곡선·경사에 맞춥니다. 인접 교차로나 도로 끝 때문에 공간이 부족하면 화살표만 생략하고 방향 설정은 저장합니다. 패널에서 생략 여부를 확인할 수 있습니다. 현재 사용자 맵 검사에서는 16개 진입 방향 중 2방향의 화살표 공간이 부족합니다.

`BoraRoads.Junctions`의 각 교차로에 `LaneKey`와 `LaneDirections`를 저장합니다. 각 ObjectValue는 실제 도로를 참조하고 진입 arc sign, 차로별 방향 비트(직진=1/좌회전=2/우회전=4)를 기록합니다. 교차로 재생성 시 도로 구성과 종방향 순서로 기존 설정을 대응시킵니다. T↔십자 변화도 인접한 동일 도로 쌍을 찾아 유지하며, 제거된 방향은 현재 출구에 맞춰 정리합니다. 교차로가 새로 삽입되어 기존 대응을 확정할 수 없으면 새 기본값을 사용해 다른 교차로의 설정을 잘못 옮기지 않습니다.

차로 방향은 신호와 연결됩니다. 해당 진입로의 차로 중 좌회전이 하나라도 있으면 좌회전 화살표와 전용 단계를 생성합니다. 마지막 좌회전 지정을 끄면 둘 다 제거합니다. 우회전 전용 신호는 추가하지 않으며 실제 차량 주행 제어는 아직 포함하지 않습니다.

### 횡단보도 · 정지선 · 신호등

도로 탭 아래 **교차로 시설**에서 횡단보도·정지선·신호등을 각각 켜거나 끕니다. 횡단보도 깊이(2~6m), 교차로에서 띄우기(0~5m), 정지선 간격(0.5~4m), 초록불 유지 시간(5~60초)은 슬라이더로 조절하고 놓을 때 적용합니다. 숫자 입력은 **교차로 시설 적용**으로 반영합니다. 설정은 전체 도로망의 `BoraRoads` 속성에 저장합니다.

기존 도로는 **교차로 다시 계산**을 누르면 시설을 추가합니다. 새 교차로를 만들거나 도로 폭·점을 바꾸면 시설도 함께 갱신합니다. 횡단보도와 정지선 구간에서는 기존 차선을 끊고, 정지선은 우측통행의 진입 차로에만 표시합니다. 흰 노면 표시는 충돌하지 않으며 곡선·경사를 따라 생성됩니다.

도로 끝이 짧거나 인접 교차로와의 공간이 부족하면 해당 방향의 노면 표시를 생략하고 패널에 **표시 공간 부족 n방향**을 표시합니다. 기존 도로와 교차로 형상은 유지합니다. 간격을 줄이거나 도로를 늘려 다시 계산할 수 있습니다. 신호등은 유지합니다.

차량 신호등은 Tripo의 가로형 3색 본체와 지주·점등 부품을 사용합니다. 좌회전이 있는 진입로는 본체의 한 칸을 재사용한 경량 확장 메시를 붙여 빨강·황색·좌회전 화살표·직진 초록의 4구 형태로 만듭니다. 확장 메시 2,570 triangles를 포함해 본체는 9,070 triangles입니다. 편집 상태에서는 빨강으로 보입니다.

Play에서는 **진입로 1 직진 → 진입로 1 좌회전 → 다음 진입로의 직진/좌회전 → 보행** 순서입니다. 없는 방향은 건너뛰고 각 차량 단계 뒤 황색 3초·전체 적색 1.5초를 둡니다. 기울어진 T자·십자에서도 동시에 한 진입로의 한 진행 방향만 보호합니다. 좌회전 중에는 원형 적색과 초록 화살표가 함께 켜집니다. **직진 초록불 유지(5~60초)**와 **좌회전 화살표 유지(4~40초)**를 드래그로 조절합니다. 같은 서버의 공용 시각을 사용합니다.

우회전은 별도 램프 없이 `StopAndYield` 정책과 `RightTurnAllowed`·`RightTurnMustYield` 속성을 제공합니다. 보행 초록·점멸·종료 대기와 전체 적색 대기 동안 허용값이 꺼집니다. 이 값은 보호 우회전 신호가 아니며, 차량 AI·충돌 감지·강제 정지는 아직 구현하지 않았습니다.

v0.5에서는 Tripo로 만든 **보행자 신호등**을 각 횡단보도 양쪽에 배치합니다. 빨간 서 있는 사람과 초록 걷는 사람은 별도 점등 부품입니다. **보행 신호** 버튼으로 켜거나 끄고, **보행 초록불 유지(6~60초)**·**점멸(2~10초)**을 드래그로 조절합니다. 기본값은 초록 10초와 점멸 4초입니다.

보행 신호가 있는 교차로는 모든 직진·좌회전 단계가 끝난 뒤 **차량 전체 빨강 상태에서 보행 초록 → 보행 초록 점멸 → 전체 빨강 1.5초** 순서로 움직입니다. 이 구간에는 모든 차량 방향이 빨강이며 좌회전 화살표도 꺼집니다. 보행 신호를 끄거나 모든 횡단보도가 생략된 교차로에는 보행 시간을 추가하지 않습니다. 횡단보도가 없는 방향에는 보행 신호등도 만들지 않습니다. 편집 상태에서는 빨간 사람이 켜집니다. 신호에 따른 차량 강제 정지나 보행자 AI 제어는 아직 없습니다.

신호등은 현재 PC의 `rbxasset://BoraRoadKit/TrafficSignal.mesh`와 `.png`를 사용합니다. 온라인/다른 PC 배포에는 Roblox 에셋 업로드와 경로 교체가 필요합니다. 현재 메시는 `assets/traffic/retopology/TrafficSignal_Clean.mesh`와 동일한 정리본(7,581 triangles)입니다. 4구용 확장 칸은 이 메시에서 추출한 2,845 triangles이며 렌즈 위치는 `src/TrafficAssetLayout.luau`에 기록합니다.

보행 신호등은 같은 폴더의 `PedestrianSignal.mesh`·`.png`를 사용하며 현재 정리본은 2,514 triangles입니다. `assets/traffic/retopology/PedestrianSignal_Clean`의 메시·텍스처를 적용했습니다. 기존 기둥과 헤드 위치를 보존하고 빨강·초록 표시를 새 렌즈 중심에 맞춥니다. 출처와 표시 위치는 `pedestrian-manifest.json`에 기록했습니다.

- `Workspace.BoraRoads`의 도로 Model마다 `Nodes`의 Vector3Value 순서와 Width/Lanes/Sidewalk/Curve/Lift/ObjectId를 저장합니다. 이후 자동 이미지 추출도 이 중심선 입력으로 연결할 수 있습니다.
- 도로 폭과 인도 폭은 m, 월드 위치는 studs입니다. 기본 변환은 Roblox 표준인 1 stud=0.28m입니다.
- 완만한 Hermite 중심선을 샘플링하고 공유 단면으로 노면과 인도를 생성합니다. 삼각형마다 두 WedgePart를 사용하며 차선은 별도 얇은 부품입니다. 급한 되접힘·25% 초과 경사·너무 좁은 차선은 적용하지 않습니다.
- 구조를 완성한 뒤 교체해 잘못된 입력이 기존 도로를 없애지 않도록 합니다. 이전 Nodes/Geometry는 세션 Undo용으로 보관합니다. 편집 횟수에 따라 세션 메모리가 늘 수 있습니다.
- 참고 지도는 회전·크기·진하기·위치와 이미지 비율을 저장합니다. 큰 지도는 부품 크기 제한에 맞춰 나눠 표시합니다. 축척 변경은 첫 기준점을 고정하고 지도만 바꾸며, 기존 도로는 이동하지 않습니다.
- 지도는 표면 Texture로 표시해 낮은 노면을 가리는 SurfaceGui의 깊이 겹침을 피합니다. 기본 지도 방향은 Studio의 표준 Top 시점과 맞춥니다.
- 참고 지도는 Play에서 숨깁니다. 생성 도로는 일반 저장 부품이라 별도 재생성 스크립트가 필요 없습니다.

## 이번 범위의 한계

자동 이미지 인식, 지형 자동 성토, 터널·교량, 전체 도로망의 일괄 축척 변경은 포함하지 않습니다. 작은 구간을 먼저 작업하세요. 곡선 도로 부품 수가 많아질 수 있어 큰 지역의 모바일 성능은 별도 검토가 필요합니다.

지도는 현재 PC의 `rbxasset://BoraRoadKit/MapReference.png`를 참조하며 공개 업로드하지 않았습니다. 다른 지도는 사용할 수 있는 Roblox 이미지 ID와 원본 가로·세로 픽셀을 입력합니다. 새 로컬 이미지 파일은 설치 폴더에 복사하는 과정이 필요합니다. PNG 파일 선택/드롭으로 즉시 영구 가져오는 기능은 아직 없습니다.

## 빌드와 검사

기존 `tools/build_tree_v4.luau` 진입점이 나무·도로 플러그인을 함께 빌드하고 같은 `Ro.rbxlx`의 도구 소스와 신호등 점등 부품을 갱신합니다. 신호등의 기존 지주·참조 ID와 도로·차로 설정은 유지합니다. 지도가 없을 때만 초기 참고 지도를 추가합니다. 저장된 지도 위치·축척과 기존 도로는 덮어쓰지 않습니다. `tools/install_tree_v2.ps1`이 두 플러그인과 로컬 에셋을 설치합니다.

Studio가 열려 있을 때 `lune run tools/build_tree_v4.luau --kits-only`로 프로젝트를 건드리지 않고 패키징·컴파일만 할 수 있습니다. 실제 프로젝트 갱신 전에는 Studio에서 저장하고 닫습니다.

`tests/roads.luau`는 노면 면적·수평 충돌면·곡선·경사·ID 유지·실패 시 보존·저장 후 재편집·미리보기 비충돌·지도 분할·축척 기준점·지도 방향·소스 컴파일을 검사합니다. `tests/project_update.py`는 유일한 Place와 맵 배치·사용자 데이터 보존을 검사합니다.

2026-10-15 Studio에서 두 점 축척 계산, 3점 도로 생성, 제어점 드래그, 폭 슬라이더(7m→12.2m), 실행 취소, 지도 폭 4000/6050 studs의 분할 표시를 확인했습니다. 최종 표시 방식에서 기본 높이 보정 0.05m의 2점 도로 노면·차선도 확인했습니다. 시험 도로와 시험 축척은 남기지 않았으며, 실제 거리 축척은 사용자가 정해야 합니다.

참고: [Roblox 단위](https://create.roblox.com/docs/physics/units), [PluginGui 마우스 위치](https://create.roblox.com/docs/reference/engine/classes/PluginGui/GetRelativeMousePosition).

`tests/junctions.luau`는 중간 스냅·끝점 스냅 유지·절개 위치·둥근 모서리·차선 정리·참조 저장/재불러오기·기존 도로 이동 추종·폭/높이 변경·분리 복구·근접 교차로 거부·실패 시 보존·경사진 방향과 완만한 곡선을 검사합니다. 2026-10-16 Studio에서 기존 사용자 도로에 시험 T자를 붙이고 연결점을 드래그한 뒤 폭을 7m→10.2m로 조절했습니다. 세 작업을 실행 취소해 사용자 도로를 복구했습니다.

`tests/crossroads.luau`는 자동 십자·반대편 T 합치기·네 모서리·충돌 면적·절개와 차선·폭/점 변경·분리 및 삭제 복구·저장 참조·다중/곡선 교점·높이 분리·잘못된 교차로의 원자적 거부를 검사합니다. v0.3은 사용자 요청에 따라 Studio 실행이나 가상 데스크톱 전환 없이 자동 형상 검사로 확인했습니다. 실제 Studio 화면에서의 v0.3 조작 확인은 아직 하지 않았습니다.
