# 건물 편집기 · v1.4.0

## 층별 도면 · 벽·계단·엘리베이터

건물을 선택하고 **플러그인 → 보라동 건물 → 층별 도면**을 누릅니다. 기존 건물 인스펙터에도 **층별 도면 · 벽 / 계단 / 엘리베이터** 버튼이 있습니다. 처음에는 1층을 표시하며 위의 화살표나 층 번호로 각 층을 선택합니다. 도면 아래가 건물 정면 출입구 쪽입니다. 도면은 0.25m 격자와 건물 기준 미터 좌표를 사용합니다.

- **벽 선:** 시작점과 끝점을 차례로 클릭합니다. 두께는 0.08~0.4m이며 해당 층 천장까지 벽을 세웁니다.
- **벽 블록:** 사각형의 두 모서리를 클릭하면 해당 면적에 벽 블록을 세웁니다.
- **문 넣기:** 벽 선을 클릭해 문틀과 열린 문짝이 있는 폭 1.2m 개구부를 냅니다. 같은 벽의 다른 곳을 클릭하면 옮기고, 문 위치를 다시 클릭하면 지웁니다. 벽 선당 하나이며 벽을 옮기거나 회전하면 함께 움직입니다. 문짝은 열린 상태로 고정됩니다.
- **계단:** 위치를 한 번 클릭합니다. 3×4.8m의 왕복 계단이며 현재 층에서 바로 위층으로 연결됩니다. 발판·중간 계단참·난간을 만들고 윗층 바닥에는 실제 구멍을 냅니다. 꼭대기 층에는 놓을 수 없습니다.
- 배치한 계단은 바로 선택되어 피봇으로 옮길 수 있습니다. 위층 도면의 **아래층에서 올라오는 계단**을 끌어도 같은 계단과 바닥 구멍이 움직입니다. 같은 자리에 현재 층 계단이 있으면 현재 층 계단이 우선 선택됩니다.
- **엘리베이터:** 위치를 한 번 클릭합니다. 2.8×2.8m 승강로와 객실·전 층 출입문·호출 버튼을 만듭니다. 어느 층 도면에서 놓아도 전 층에 같은 위치로 연결하며 윗층 바닥을 뚫습니다.
- **선택·이동:** 벽·블록·계단·엘리베이터를 클릭하면 도면의 중심에 피봇이 표시됩니다. 빨간 화살표는 X축, 파란 화살표는 Z축 이동이며 가운데 핸들은 자유 이동입니다. 이동은 0.25m 간격입니다. 금색 링의 **↻** 핸들을 끌어 회전합니다. 벽은 중심과 길이를 유지하며 15° 단위로, 블록·계단·엘리베이터는 90° 단위로 회전합니다.
- **정밀 배치:** 위쪽 **X / Z / 각도 / 두께**의 ↔ 라벨을 좌우로 끌거나, 숫자를 입력하고 **값 적용** 또는 Enter를 누릅니다. X·Z는 드래그 시 0.25m 단위이며 벽의 좌표는 양 끝점의 중심입니다. 각도는 벽 15°, 블록·계단·엘리베이터는 90° 단위로 끌 수 있습니다. 두께는 0.01m 단위(0.08~0.4m)이며, 벽을 선택하면 그 벽을 바꾸고 없으면 다음에 그릴 벽의 기본값을 바꿉니다. 놓을 때 실제 건물에 한 번 적용합니다. Esc로 취소하고 Ctrl+Z로 완료한 조작을 되돌립니다.
- **90° 회전**, **선택 삭제**, **지우개**도 사용할 수 있습니다. 선택이 없을 때 회전 버튼은 새 계단·엘리베이터의 배치 방향을 바꿉니다. 피봇은 이 2D 도면 안에 표시됩니다.
- **다음 층에 복사:** 해당 층의 벽·블록·계단을 빈 다음 층에 복사합니다. 마지막 층으로 복사할 때 계단은 제외합니다. 엘리베이터는 이미 전 층에 연결되어 중복 복사하지 않습니다.
- **전층 복사:** 현재 층을 원본으로 두고 나머지 층의 벽·블록·계단을 덮어씁니다. 벽에 붙은 문도 복사하며, 꼭대기 층에는 계단을 놓지 않고 전 층 공용 엘리베이터는 그대로 둡니다. **복사 되돌리기**로 가장 최근 복사 직전의 배치를 복원합니다. 복사 후 다른 도면을 수정했다면 새 편집을 덮어쓰지 않도록 복원 버튼은 비활성화됩니다. Studio의 Ctrl+Z로는 순서대로 되돌릴 수 있습니다.

완성한 선이나 배치·이동·삭제는 실제 모델에 즉시 적용되고 각각 Ctrl+Z로 되돌립니다. 첫 점만 찍은 상태는 Esc로 취소합니다. 외벽 밖 배치, 계단/엘리베이터와 벽·블록의 겹침, 위층 출구를 막는 벽, 남은 도면을 벗어나는 건물 크기·층수 변경은 거절하고 이전 모델을 유지합니다. 도면은 건물의 `BB_PlanJSON` 속성에 저장하며 이동·회전 후에도 건물 기준 위치를 유지합니다.

첫 도면 편집부터 자동 칸막이·실내 상가 진열 대신 사용자가 그린 도면을 적용합니다. 비어 있는 명시적 도면과 아직 그리지 않은 기본 도면을 구분합니다. 계단·엘리베이터를 지우면 바닥 구멍도 막힙니다. 생성기가 소유한 `Geometry`를 다시 만들므로 직접 추가한 사용자 소품은 계속 Geometry 밖에 두세요. 스냅 격자·2D 부품은 정확한 배치를 돕지만 전체 동선·방 구성·문과 가구 배치까지 자동 설계하지는 않습니다.

Play에서는 층별 버튼 앞에서 **E**로 엘리베이터를 호출하고, 안으로 들어가 객실 패널에서 **E → 이동할 층**을 선택합니다. 문 닫힘 → 객실 이동 → 도착 후 문 열림 순서이며 호출을 대기열로 처리합니다. 문턱에 사람이 있으면 문을 열어두고 출발을 미룹니다. 탑승자는 이동 중 잠시 고정해 객실과 함께 움직이고 도착·사망·엘리베이터 제거·실행 오류 때 해제합니다. 현재 탑승 대상은 플레이어 캐릭터이며 차량·NPC 운반은 포함하지 않습니다.

## 보라빌라 101 동선

`Workspace.BoraNeighborhood_01.Buildings.BoraVilla`의 기존 건물을 사용합니다. 정면 출입구로 들어가면 왼쪽 계단과 오른쪽 엘리베이터가 1~3층을 잇습니다. 2·3층에는 엘리베이터와 계단을 잇는 복도, 앞쪽 방으로 통하는 문을 두었습니다. 기존 통짜 윗층 벽체와 막힌 천장은 외벽과 개구부가 있는 바닥으로 바꿨으며 기존 창틀·유리·발코니·간판·앞마당과 그 외 맵 배치는 그대로 둡니다. 도면만 바꿀 때는 이 외관을 유지하고, 건물 치수나 외관 설정을 바꾸면 일반 모듈형 외관으로 다시 조립합니다.

최초 반영에 사용하는 빌드 옵션은 `--villa-stage` 및 `--villa`입니다. 단계 파일과 검증 결과는 `BORA_VILLA_WORK`에 지정한 `99_Code_Work` 아래의 작업 폴더에 저장합니다. 이 변환은 예전의 통짜 윗층 부품이 남아 있는 보라빌라에만 적용됩니다. 검증은 기존 정면 출입구, 계단 머리 여유, 문과 복도, 엘리베이터 왕복을 포함합니다. 실제 Studio Play 확인은 별도입니다.

**바주카와 건물 파손:** 스폰 앞 오른쪽의 바주카포 거치대에서 **G**를 누르면 장착됩니다. 대상을 가리키고 **좌클릭**하면 발사하며 재장전은 약 1.15초입니다. Studio Play에는 정면에 쏴볼 시험 벽이 생깁니다. 로켓은 경로의 첫 충돌 위치에서 폭발합니다. 폭발 반경 안의 로컬 편집기 건물(`AssetKind=BoraBuilding`)은 해당 벽 구간부터 부서지며, 한 층에서 지지 벽의 52% 이상을 잃고 두 면 이상에 손상이 누적되면 바로 위층부터 차례로 떨어집니다. 유리와 일반 칸막이 손상은 지지력과 별개입니다. 보라빌라의 1층 옆벽·뒤벽을 여러 방향에서 쏘면 전체 시험을 할 수 있습니다.

도면에서 추가한 벽 선·벽 블록과 문이 달린 벽은 로켓이 닿은 구간이 부서집니다. 맞지 않은 문틀과 주변 바닥은 그대로 남습니다. 편집기 건물 아래에 직접 추가한 벽 모양의 고정 Part도 맞으면 부서집니다. 건물과 별개로 둔 고정 Part는 이름에 `Wall` 또는 `벽`이 있거나 `BoraBreakableWall=true` 속성을 붙이면 파손 대상으로 인식됩니다.

외벽이나 슬래브의 지지를 잃은 창문·창틀·층 경계 마감재와 옥상 설비는 폭발 범위 밖에서도 떨어집니다. 지붕과 천장은 남은 벽에 연결된 구간이 버팁니다. 파편 한도에 도달하면 지지를 잃은 부품은 즉시 제거됩니다.

건물 파손은 실행 중에만 일어나며 저장된 도면·건물 모델을 바꾸지 않습니다. 파편은 중력과 충돌을 받고 약 10초 후 정리합니다. 이전 E키 데모를 대신하는 서버 패키지는 `--rocket-stage`로 `BORA_BUILDINGS_WORK`에 만들고, Studio에서 기존 편집을 저장하고 닫은 뒤 `--rocket`으로 같은 `Ro.rbxlx`에 넣습니다.

실행 코드는 `BoraBuildingRuntime`(ServerScriptService)과 `BoraBuildingClient`(StarterPlayerScripts)입니다. 클라이언트의 층 선택은 서버가 실제 객실 내부인지와 층 번호·요청 간격을 검사한 뒤 처리합니다. 배포 빌드와 Studio에서 새 건물을 만들거나 편집할 때 두 코드를 설치합니다. 기존 자동차·도로·나무 런타임은 수정하지 않습니다.

`dist/BuildingFloorPlanPreview.rbxmx`는 벽·3층으로 이어지는 계단 두 개·전 층 엘리베이터를 조립한 모델 미리보기입니다. 별도 Place나 테스트 맵이 아니며 실제 맵에 자동으로 삽입하지 않습니다. `dist/preview/building-floorplan-cutaway.png`는 그 모델의 1층을 절단한 Blender 렌더이고 `building-floorplan.svg`는 같은 레시피의 평면도입니다. Studio 화면 캡처가 아닙니다.

유일한 `Ro.rbxlx`의 기존 네 건물을 편집기에 연결합니다. 기존 위치·부품·간판·수동 편집과 나머지 맵을 보존하고, 정리한 벽등만 각 건물에 두 개씩 추가합니다. 최초 적용 전까지 원래 건물 모양을 자동으로 다시 만들지 않습니다. 설치된 **플러그인 → 보라동 건물 → 건물 편집**을 엽니다. 건물 내부 부품 하나를 선택해도 해당 건물을 찾습니다.

- 종류: 상가·카페·약국·마트·빌라·아파트·주택.
- 층수: 1~24층. 상층 높이·1층 높이·가로·깊이·창문 폭·앞마당 깊이는 슬라이더 또는 숫자로 변경합니다.
- 한글 간판 이름(48자), 간판·발코니·차양·벽등/옥상 장식의 켜기/끄기, 외벽·띠·창틀/간판의 HEX 색상.
- 슬라이더는 놓으면 적용합니다. Esc를 누르거나 드래그 중 창을 닫으면 진행 중인 변경을 취소합니다. 숫자·간판·종류·색상·켜기/끄기를 입력한 뒤에는 **선택한 건물에 적용**을 누릅니다. Ctrl+Z/Ctrl+Y로 되돌립니다.
- **건물 설치**를 누르고 평평한 지면을 클릭하면 새 건물을 놓습니다. 방향은 설치 전 각도로 지정합니다. Esc로 취소합니다. 기존 건물은 Studio 이동·회전 도구로 움직입니다. 재편집 시 `BuildingOrigin`의 현재 위치·방향을 유지합니다.

적용은 건물 전체 크기를 늘리는 방식이 아니라 층·창틀·유리·슬래브·발코니를 치수에 맞춰 다시 조립합니다. 창 뒤에는 실제 개구부가 있습니다. 지붕·간판·1층 높이는 층수와 독립적입니다. 건물·앞마당이 저장된 도로의 차도와 겹치거나 본체가 다른 충돌 부품과 겹치면 적용을 거절합니다. 이 검사는 보수적인 박스 검사이며 문·발코니·모든 장식의 정밀 충돌이나 지형 기초를 자동 설계하지 않습니다.

생성된 부품은 각 건물의 `Geometry` 아래에 있습니다. **직접 추가하는 소품은 Geometry 밖에 두세요.** 재생성 시 Geometry 안의 수동 수정은 대체됩니다. 기존 건물 도입 과정에서는 알려진 생성 부품만 Geometry로 옮기며 추가 사용자 오브젝트는 건물 루트에 보존합니다. 건물 루트의 이름·식별자와 외부 소품은 재편집으로 바꾸지 않습니다. Undo를 위해 이전 Geometry는 Destroy하지 않고 분리 보관합니다.

현재 본체는 편집 가능한 일반 Roblox 부품입니다. Tripo로 건물 전체를 생성하지 않았습니다. 7개 종류는 상가/주거 입면·차양·재질 등의 조합이며 서로 다른 7개 고유 건축 모델을 뜻하지 않습니다. 층별 도면으로 벽·계단·엘리베이터를 배치하며, 완성된 세대·실제 점포 운영·자동 실내 설계는 포함하지 않습니다. 12층 아파트 `.rbxmx`는 생성 결과의 미리보기 자산이며 Place에 추가하지 않습니다.

## Tripo 장식과 Blender 정리

벽등은 [Tripo 생성본](https://studio.tripo3d.ai/ko/workspace/generate/eb6564a3-f49d-423b-ae56-eee45e722466)을 사용했습니다. 원본 `assets/buildings/source/WallSconce_Tripo.glb`(1,918,317 triangles)를 보존하고 단면·범위를 `assets/buildings/measurements.json`에 기록합니다. 생성본의 둥근 뒷판·동심 테두리·곡선 지지대·전구 형태를 기준으로 금속 표면과 작은 부품을 재구성합니다. 원본의 깨진 불투명 유리 대신 두께 있는 닫힌 투명 셸을 만듭니다. 원본의 구워진 음영 얼룩을 새 금속에 다시 베이크하지 않습니다.

정리본은 `assets/buildings/WallSconce_Clean.blend`, 내보내기는 `assets/buildings/local/WallSconce_*.mesh` 세 재질 부품, 총 **5,784 triangles**입니다. 동일 메시를 반복 사용하며 각 건물의 크기를 바꿔도 장식 크기는 늘리지 않습니다. 원본과 정리본의 솔리드·실제 와이어프레임을 확인합니다. `dist/building-decoration-mesh-validation.json`은 저장 후 다시 연 파일의 닫힘·퇴화 면·노멀·UV 검사이며 시각적 품질 승인과 구분합니다. 로컬 rbxasset 경로이므로 온라인 배포 시 별도 Roblox 업로드가 필요합니다.

## 빌드·설치·검증

Studio에서 기존 편집을 `Ro.rbxlx`에 저장하고 닫은 상태에서 실행합니다. 도구는 Studio를 실행하거나 활성화하지 않습니다.

```powershell
lune run tools/build_tree_v4.luau --buildings-stage
lune run tests/buildings.luau
lune run tests/building_plugin.luau
lune run tests/building_floorplan.luau
lune run tests/building_plan_editor.luau
lune run tests/building_elevator.luau
lune run tests/building_elevator_runtime.luau
lune run tests/building_elevator_client.luau
python tests/building_project.py
lune run tools/build_tree_v4.luau --buildings
powershell -ExecutionPolicy Bypass -File tools/install_buildings.ps1
```

Stage는 `.rbxmx`와 JSON만 만듭니다. 적용 직전에 원본 Place·소스·패키지·메시 해시를 대조하고 원자적으로 같은 `Ro.rbxlx`만 저장합니다. 새 Place·백업 Place·테스트 맵을 만들지 않습니다. 기존 건물의 원래 부품 속성과 다른 서비스·자동차·도로·나무·집기 보존을 검사합니다. 도입된 건물은 반복 적용해도 다시 생성하지 않습니다.

`tests/buildings.luau`는 실제 생성기의 28개 조합, 치수·간판·이동·저장 왕복·개구부·사용자 소품·잘못된 입력을 검사합니다. `tests/building_plugin.luau`는 실제 플러그인 콜백을 UI/History 어댑터에서 실행합니다. Studio 자체의 패널·Undo 동작과 Play 화면을 실행한 검사는 아닙니다. `tests/building_project.py`는 실제 디스크 Place를 읽어 도입 시 보존과 메시 내보내기를 검사합니다.

도면 검사는 실제 벽·바닥 타일 면적·계단의 0.18m 이하 단높이·위층 도착 높이·4방향 회전·저장 왕복·잘못된 편집의 원자성을 확인합니다. 피봇 검사는 실제 UI 콜백에서 축 제한·자유 이동·15°/90° 회전·벽 길이 보존·좌표 입력·미리보기와 완료 시 한 번 적용·Esc/층 변경 취소를 실행합니다. 이동 후 기존 바닥 구멍 복구와 새 구멍 생성도 실제 3D 부품으로 확인합니다. 엘리베이터의 실제 이동 컨트롤러·탑승자 이동·문·대기열·문턱 감지·삭제/오류 해제·서버 요청 검증·클라이언트 층 선택 콜백도 실행합니다. Studio 도면의 실제 클릭과 엔진의 Humanoid 보행·네트워크 환경까지 실행한 Play 검사는 별도입니다.

`tools/render_neighborhood.py -- --buildings` 또는 `-- --apartment`의 PNG는 실제 생성 부품을 Blender에서 렌더한 미리보기입니다. Studio 캡처가 아니며 미리보기의 새 본체가 기존 네 건물을 자동으로 교체했다는 뜻은 아닙니다.
